# Headset Desk 0.4.0 Beta — redesigned app

A cleaner, calmer Windows app for **WH-1000XM5** and **WH-CH720N**. Same behaviour and safety rules as 0.3.0; new look.

Windows 11 x64. Installs for your account without administrator rights; installing over 0.3.0 upgrades it in place (quit the old version from the tray first). The app and installer are unsigned, so Windows SmartScreen may show an unrecognized-app warning.

## What's new

- **New design.** Grouped, rounded tiles in the style of system settings panes, neutral greys, and colour only where it means something: blue for Noise Cancelling and the primary action, green for connected and Ambient, amber for experimental and low battery.
- **Device card** with an original headphone drawing, a status dot with update age, and a battery gauge next to the percentage.
- **Segmented noise control** (Noise Cancelling / Ambient / Off) with a one-line description of the current mode. The current mode stays readable when controls are off.
- **Experimental controls** is now a labelled switch row that explains why it is unavailable when no headset is connected.
- **Equalizer** with slim sliders that fill from 0 dB, so boosts and cuts read at a glance. Unknown EQ shows dashes and no handles, never a fake 0.
- **Details** folds firmware, reported codec and last refresh into one row you can expand.
- Buttons and the device picker are drawn by the app, so light and dark mode look the same on every Windows setup.

## Unchanged

Controls start off and switch off on disconnect, device change, reconnect or any failure. Each change is validated, sent once, ACKed and confirmed by a fresh readback; nothing is retried or replayed. EQ edits stay local until **Apply**; **Reset** discards them. Close hides to the tray; tray **Quit** exits. One headset session at a time. No firmware updates, power commands, cloud, analytics or startup entry.

## Evidence

Reads are verified on XM5 firmware 2.5.1 and CH720N firmware 1.1.4 (reviewed captures). With 0.3.0 the owner observed XM5 Off → NC → Ambient 1 → Off working with readback confirmation, and reports the app working on the CH720N. These are owner observations, not packet captures, so write confidence in code stays **UNKNOWN** and the controls remain an experimental opt-in. Details: [hardware evidence](https://github.com/ashwinpr15/headset-desk/blob/v0.4.0-beta.1/docs/hardware-validation.md).

## How this build was made

Built and checked by the [desktop workflow](https://github.com/ashwinpr15/headset-desk/actions/workflows/desktop-release.yml) on GitHub's Windows runners with Qt 6.8.3 (mingw_64) and MinGW GCC 13.1.0, the same kit as 0.3.0. The run executed all offline tests, captured simulated screenshots with only the bundled runtime on PATH, then silently installed, hash-checked, launched and uninstalled the installer. Screenshots and logs are in `headset-desk-v0.4.0-beta.1-validation.zip`. No commands were sent to physical headphones during development.
